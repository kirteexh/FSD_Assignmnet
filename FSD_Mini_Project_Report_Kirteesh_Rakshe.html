1. Introduction and Objectives

1.1 Project Overview and Clinical Context

Modern pharmaceutical retail and hospital dispensaries operate in highly demanding, clinical environments where precision, speed, and regulatory compliance are essential to patient well-being and commercial sustainability. Unlike conventional commodity retail systems, pharmaceutical operations deal with potent, regulated chemical compounds, strict shelf-life expiration dates, batch traceability mandates, schedule-restricted narcotics, and dynamic manufacturer price revisions.

PharmaCare is a full-stack, enterprise-grade pharmacy management web platform designed to streamline retail and hospital dispensary workflows. By combining a contemporary Next.js 14 frontend, a decoupled Express.js REST and Socket.IO backend, and dual-mode MongoDB Atlas persistence, PharmaCare modernizes traditional drug dispensing, automated batch allocation, and financial auditing.

1.2 Problem Statement & Industry Challenges

A comprehensive operational analysis of independent pharmacies and dispensary chains reveals several pervasive failure modes arising from legacy desktop software or manual paper-based ledger systems:

  • Dead Stock & High Expiry Write-Off Losses: In conventional retail dispensaries, staff grab the most accessible medication boxes from shelves during rush hours. This human tendency leaves earlier-received batches lingering in the back of racks until they expire, generating significant recurring financial losses for pharmacy owners.
  • Slow Checkout Bottlenecks & Prescription Verification: Manual batch number entry, manual tax calculations, and disconnected verification of Schedule-H prescription drugs create prolonged queues at dispensary counters, risking patient frustration and data entry mistakes.
  • Inventory Desynchronization & Stock-Outs: Without real-time inventory synchronization, dispensaries often run out of essential, life-saving antibiotics, insulin, and cardiac formulations without advance warning.
  • Inadequate Auditing & Role Segregation: Traditional single-tier desktop systems fail to provide robust role-based access control (RBAC), leaving critical operations like stock adjustments, clinical disposal write-offs, and price updates vulnerable to untracked human error or insider theft.

1.3 Key Project Objectives

The primary objectives established for the development of the PharmaCare platform are as follows:

  • Intelligent First-Expiry, First-Out (FEFO) POS Billing: Design and implement an automated point-of-sale checkout engine that programmatically selects and deducts inventory from the earliest expiring batch, completely eliminating human bias in dispensing aged stock.
  • Batch-Level Traceability & Clinical Audit Trails: Maintain granular lifecycle history for every individual pharmaceutical batch, including manufacturer details, manufacturing and expiry dates, purchase costs, MRP, supplier GSTINs, and audited stock adjustments.
  • Proactive Shelf-Life Expiry Monitoring: Provide real-time categorization of dispensary inventory into clinical urgency tiers (<7 days, <30 days, <90 days, and expired), complete with formal clinical write-off logging.
  • Real-Time Stock Alerts via WebSockets: Integrate bidirectional Socket.IO WebSockets to broadcast instant, asynchronous notifications to all active workstations whenever any critical medicine breaches its minimum reorder threshold.
  • Robust Role-Based Security & Production DevOps: Enforce JWT authentication with password hashing (bcryptjs) separating Store Administrator and Cashier roles, and package the complete system with Docker multi-stage containers and automated GitHub Actions CI/CD.

1.4 Target Audience and User Roles

The system explicitly caters to two distinct operational user classes with strictly partitioned permissions:

  • Store Administrator (Pharmacist-in-Charge / Owner): Authorized with comprehensive administrative privileges including medication catalog authoring, batch creation, audited stock quantity adjustments, clinical disposal approvals, purchase order procurement, staff credential provisioning, and executive financial reporting.
  • Dispensary Cashier (Sales Staff): Authorized with frontline operational permissions focused on rapid POS barcode billing, patient prescription recording, customer invoice generation, held bill caching, and real-time stock catalog lookups.

2.3 Data Flow & FEFO Algorithmic Design

The core mathematical and business innovation in PharmaCare is its First-Expiry, First-Out (FEFO) dispensing algorithm. When an item is added to the dispensary checkout cart with requested quantity Q, the backend queries all unexpired, active inventory batches for that medicine and orders them in ascending chronological order of expiration dates (expiryDate ASC). As detailed in the flowchart in Figure 2, the algorithm deducts stock sequentially from the earliest expiring batch, cascading across lots until the quantity is fulfilled.

3. Implementation with Screenshots

3.1 Authentication & Role-Based Access Control (RBAC)

PharmaCare implements rigorous, stateless authentication utilizing JSON Web Tokens (JWT). Upon successful credential verification via bcrypt comparison (salt rounds: 10), the server issues a signed JWT payload containing the user's unique ID, username, email, and authorization role (admin or cashier). Protected backend routes are guarded by high-order middleware functions (requireAuth and requireAdmin).

3.2 Intelligent FEFO POS Billing Interface

The Point of Sale billing interface is optimized for high-speed counter operations. Cashiers can instantly lookup medicines via live text queries or barcode scanner inputs. As shown in Figure 3, the POS terminal features a split-pane layout: the left pane houses the real-time active cart displaying medicine names, automatically allocated batch numbers, expiry months, unit prices, and sub-totals. The right pane computes live tax breakdowns, including Central GST (CGST) and State GST (SGST), discounts, round-off adjustments, and payment method toggles.

4. Deployment and DevOps

4.1 Multi-Container Docker Architecture

PharmaCare is fully containerized using Docker to eliminate environment discrepancies and ensure rapid, reproducible deployments across developer machines, staging clusters, and production cloud servers. Both the Next.js frontend client and Express.js backend server utilize optimized multi-stage Dockerfiles, cutting final image footprints by over 65%.

4.2 Docker Compose Runtime Orchestration

The multi-service ecosystem is orchestrated via Docker Compose (docker-compose.yml and docker-compose.prod.yml). The orchestration defines four coordinated services interconnected via an isolated internal bridge network:

  • pharmacare-server: Node.js Express REST API & Socket.IO runtime executing on port 5001 with automated healthcheck probes (wget /api/health).
  • pharmacare-client: Next.js 14 SSR frontend serving on port 3000, depending on healthy server status.
  • pharmacare-proxy (Nginx): Acts as an edge reverse proxy routing incoming port 80/443 traffic to the client and /api calls to the backend container.
  • pharmacare-mongo: Containerized local database service with persistent Docker volume mappings.

4.3 Automated CI/CD Pipeline via GitHub Actions

Continuous Integration and Continuous Deployment (CI/CD) is automated using GitHub Actions (.github/workflows/ci.yml). As visualized in Figure 7, every git commit pushed to the main branch or Pull Request automatically triggers a 3-stage validation pipeline: backend tests, frontend build, and Docker image compilation.

Figure 7: PharmaCare DevOps Architecture and GitHub Actions CI/CD Pipeline Workflow

4.4 Production Cloud Deployment & Security Hardening

The live production application is deployed on the Render cloud platform with MongoDB Atlas cloud clusters. Production security hardening measures implemented include Helmet security headers, Express rate limiting on auth endpoints, CORS origin restriction, and cryptographic password salting with bcryptjs.

5. Conclusion and Future Scope

5.1 Summary of Accomplishments

The PharmaCare Mini-Project successfully demonstrates the design, full-stack engineering, and cloud deployment of a robust, enterprise-grade pharmacy management application. Key project milestones accomplished include:

  • Elimination of Expiry Losses: The automated FEFO algorithm successfully dispenses earliest expiring medicine batches, solving the primary cause of dead inventory in retail pharmacies.
  • Rapid Counter Throughput: The streamlined POS checkout interface reduces customer transaction time from minutes to seconds with automatic tax computation and receipt generation.
  • Full Regulatory Compliance: Batch-level traceability and mandatory Schedule-H prescription recording ensure compliance with Indian drug regulatory mandates.
  • Production-Ready DevOps Pipeline: Containerization with Docker, multi-service orchestration with Docker Compose, and automated CI/CD via GitHub Actions establish an enterprise standard of maintainability.
